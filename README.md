# 技术就绪度与制造成熟度评价系统

机械工业仪器仪表综合技术经济研究所（ITEI）技术就绪度（TRL）与制造成熟度（MRL）评价系统。企业自助注册、逐条自评、上传佐证，逐级提交审核。企业提交后，由评价机构决定审核方式：

- **自行审核**：评价机构逐级审核通过或退回；
- **指派专家评审**：评价机构按技术领域选 3 位专家逐条评审，意见不一致时由评价机构终审。全部通过的级别审核通过，有不通过条目的级别退回企业整改，整改后再次提交，由评价机构决定复评方式。

评审完成后，评价机构按固定模板出具技术就绪度、制造成熟度或两者综合的评价报告（Word，本机有 Word 或 LibreOffice 时另出 PDF）。系统只承载流程与留痕，不做任何自动达标判断。

制造成熟度评价在其逐条细则导入前**不对外显示**（导航、申报、报告类型等入口全部隐藏），导入后自动开放，见下文“制造成熟度评价细则导入”。

## 办理流程

### 公共环节

1. 企业在登录页“企业注册”，管理员在“用户管理”审核启用。企业只能看到自己的项目。
2. 企业“申报评价项目”：选择所属技术领域、技术类型和目标等级。
3. 企业逐条给出自评结论（满足 / 不满足 / 不适用）和说明，上传佐证材料（SHA-256 存档）。只需填写目标等级以内的条目。
4. 企业逐级提交，或一次提交到目标等级。审核期间已提交级别冻结。评审方式不由企业选择。
5. 目标等级调整由企业申请、管理员审核后生效。

### 评价机构决定审核方式

企业提交后，管理员在项目评价页的“待审核”面板中处理，有两种方式：

- **自行审核**：自第 1 级起按顺序“审核通过”，或写审核意见“退回修改”。管理员可以修改已提交级别的说明文字，修改留痕、企业可见。
- **指派专家评审**：系统把已提交级别中尚未通过专家评审的条目存为提交留档，进入“专家评审”。评审期间这些级别冻结，管理员也不能直接通过或退回。

### 专家评审

1. 管理员为该轮分配 3 位专家，可按技术领域筛选；与申报企业同单位的专家会有回避提示。
2. 专家收到站内私信，在“评审任务”中签署保密与回避承诺后接受任务，也可以写明原因拒绝；拒绝或逾期的席位由管理员更换。
3. 专家逐条给出“是否通过”、满足建议和点评，可以分级保存，全部给出结论后提交。专家之间互不可见。
4. 三份意见齐全后，管理员在轮次页并排对照三位专家的意见：专家一致的条目可以批量确认；意见不一致或推翻一致意见的，须写裁定理由；判不通过的须写整改要求。
5. 提交终审结果后，系统按级别处理：自最低待审级起、全部条目通过的连续级别审核通过；有不通过条目的级别退回企业，并设整改期限；排在退回级别之后、全部通过的级别保持待审核。
6. 整改时企业只能修改未通过的条目，改完照常“提交审核”。退回的级别都重新提交后，本轮整改结束。
7. 管理员再次决定审核方式：可以自行审核，也可以“专家复评”。复评可以沿用原专家组（已签承诺，直接进入评审），也可以重新选择专家；复评只评上一轮未通过的条目。
8. 没有待整改条目时，若第三方评价组为空，系统按席位自动填入专家组。

企业看到的只有终审结论和整改要求，看不到专家姓名和专家原话。专家逾期（默认 7 天）、整改即将到期（前 2 天）和整改逾期，系统会发站内私信提醒，同一事项不重复提醒。

### 评价报告

1. 评价完成后，企业在“评价报告”填写项目概况和**自评估工作组**，预览报告并申请导出；此前报告只能在线预览。
2. 管理员在“编辑前置信息”中按固定模板逐节填写封面、扉页和第 1～3 章（任务来源、研究目标、关键技术 / 模块的设计、试制、验证情况等）。第 4 章起的评价准则、等级评价、总结和附录由系统按审核结果自动拼接。
3. 管理员审核导出申请：通过即生成新版本报告，企业随即可以下载。生成 Word 后，本机有 Word 时用 Word 转 PDF 并刷新目录页码；只有 LibreOffice 时用 LibreOffice 转换；都没有时只出 Word。
4. 在“系统设置”上传本单位的印章图片（PNG）后，报告扉页的出具单位和日期上会盖上印章。这是版式印章，不是有法律效力的电子签章。

### 站内私信、项目删除与劳务

- 页眉右上角的铃铛是站内私信。提交、审核、分配专家、终审、整改、报告出具等节点都会通知相关的人；分配专家、催办、要求整改、复评任务、报告出具这几个节点已标记为邮件节点，接入邮件服务后可直接发送。
- 企业可以删除从未提交审核的项目；管理员可以删除任何项目，须填写理由。删除的项目进入回收站，管理员可以恢复或彻底删除；彻底删除后审计日志仍保留项目名称。
- 专家每提交一轮意见，系统生成一条劳务记录，金额取“系统设置”中的默认劳务费。管理员可以修改金额、标记结算、导出 Excel 或 CSV。

## 常用命令

```bash
python manage.py check_deadlines                       # 手动执行一次期限检查（页面访问时也会每 10 分钟自动检查）
python manage.py import_experts 专家名单.xlsx          # 批量导入专家（表头同专家库页面“Excel 导入”说明）
python scripts/prepare_report_template.py              # 报告原版式模板改版后，重新生成可填充的报告模板
```

报告原版式模板放在 `data/templates/report/source/`，加工后的模板为 `data/templates/report/report_template.docx`。

环境变量：`TRL_PDF_CONVERTER`（`auto` / `word` / `libreoffice` / `none`）指定 PDF 转换方式；`TRL_DEADLINE_CHECK=0` 关闭页面访问时的期限检查。

## 制造成熟度评价细则导入

出厂时制造成熟度只有 MRL 1～10 级定义，尚无逐条细则，系统中所有制造成熟度入口处于隐藏状态。拿到正式细则后：

```bash
# 1. 按模板 data/templates/制造成熟度评价细则-模板.xlsx 整理细则
python scripts/build_seed.py mrl 制造成熟度评价细则.xlsx   # 生成 data/seed/mrl_rules_seed.csv
python manage.py import_rules                                  # 导入系统（幂等）
```

导入后无需改代码：导航“MRL评价”、项目页“制造成熟度评价”页签、申报页 MRL 板块、制造成熟度 / 综合报告类型和细则页自动出现。`python scripts/build_seed.py mrl-template` 可重新生成空白模板；`python scripts/build_seed.py trl` 从上级目录 `app_GUI.py` 重新生成技术就绪度细则。

## 工程结构

```
config/              Django 配置（SQLite；数据库与附件目录可由 TRL_DB_PATH / TRL_MEDIA_ROOT 指定）
apps/accounts        企业注册、验证码、用户管理、系统设置、权限口径（permissions.py）
apps/rules           评价体系配置（systems.py）、等级定义、评价细则、技术领域词表
apps/evaluations     项目、评价、条目、逐级提交与审核、目标等级调整、项目删除与回收站（services.py，seed_sample）
apps/evidence        佐证材料：SHA-256、软删除、权限校验下载
apps/experts         评审专家档案与主页、Excel 导入、样例专家、劳务记录页面
apps/reviews         专家评审：轮次、分配、意见、终审、整改（services.py）、期限检查（deadlines.py）、劳务（fees.py）
apps/notifications   站内私信与提醒去重
apps/reports         三类报告与导出申请：前置信息 + 系统章节 → 在线预览 + 模板 Word（docx_render.py）+ PDF（pdf.py）
apps/audit           审计流水
data/seed/           种子 CSV；data/templates/ 细则填写模板与报告模板
static/css/tokens.css   ITEI 设计体系 token（勿改）；app.css 页面样式
tests/               pytest-django（python -m pytest -q）
```

数据库迁移自第二轮起为增量迁移：升级已有数据目录时直接执行 `python manage.py migrate`。第三轮升级后，原有评价都按“管理员逐级审核”方式继续；旧审计日志会自动补记项目名称。

## 设计规范

UI 遵循 `itei-design-system`：白底 1px 边框分层、无圆角卡片、品牌 navy 为主色、每屏至多一处品牌红、渐变只用于页眉、45° 斜切品牌形状、微软雅黑字体栈、单色线性图标，状态色均配文字。
