# 评价细则自动化核验方案（逐条分析）

> 依据：本次上传附件 `评价细则.xlsx`（硬件 44 条 + 软件 33 条 = 77 条；原始工作簿未上传至公开仓库）
> 目标：对每条"具体化等级条件"，分析在**确认证明材料是否符合规则**这一环节，哪些核验动作可以自动化、如何自动化。每条记录先拆为多个事实检查点，**每个检查点**给出 3–5 个方案，**以人工审核为保底**。
> 状态：本文档随对话逐条讨论、逐条更新。条目状态标记：`待讨论` / `讨论中` / `已确认` / `已修订`。
> 原则：系统对已定义的客观事实执行自动核验，输出结论、来源和依据；冲突、缺项及无法自动处理的情况保留人工审核。当前阶段建议由评价人员确认整条 TRL 的最终结果，具体自动通过范围随讨论确定。本文是新功能的 PRD 讨论输入，候选方案不表示已经实现或已经批准。

### 0.1 自动化分级（每个方案都标注一个等级）

| 级别 | 含义 | 结论可信度 | 典型手段 |
|---|---|---|---|
| **A 客观事实核验** | 对接已核实来源或用确定性算法检查明确事实 | 仅覆盖该方法实际验证的事实；资料真实性及条目适用性另行判断 | 数据记录回查、校验位、哈希、电子签章验签 |
| **B 自动预检** | 系统按规则做形式/结构/一致性检查，分别输出匹配、冲突、缺项或未能核实 | 冲突和未知进入人工 | 印章检测、编号/日期/版本一致性、指标表比对 |
| **C AI 辅助** | 大模型读材料，按检查点输出结构化意见 + 依据摘录 + 置信度 | 仅作参考，人工必看 | Claude API 语义审查、相关性评分、缺项提示 |
| **D 人工审核** | 保底；系统提供核验卡片、复核流程与留痕 | 最终判定 | 评价人员 + 专家复核 |

### 0.4 条目模板

每条按以下结构写：

1. **条目**：编号（与系统 `CheckItem.code` 一致）、原文、支撑材料要求
2. **检查点拆解**：按"要核验的事实 / 材料类型"把条目拆成若干检查点（如：论文核验、专利核验、归属核验、内容审查……），每个检查点是一项独立的核验任务
3. **每个检查点 3–5 个方案**：同一核验任务的不同实现路径，按自动化程度从高到低排列，标注级别、做法、依赖/成本、局限；最后一个方案固定为人工审核保底。每个方案写明输入、实际步骤、输出事实、依赖/授权、成本、局限和转人工条件，区分已核实接口与候选接口
4. **检查点结论汇总规则**：各检查点结论如何合成该条目的"建议"（红/黄/绿），人工介入点在哪
5. **讨论状态与结论**

> 编号说明：软件轨道 TRL2 在 xlsx 中序号为 4,5,4,5，系统种子已改为 4,5,6,7，本文沿用系统编号。

**C1 论文自动核验**　`讨论中；方案待用户选择`

#### C1.1 核验边界与输出事实

本检查点回答：提交的材料对应哪篇论文，外部来源记录了什么发表事实，上传材料与该记录是否一致。C5 另行判断论文能否支撑本项目的基本原理。第1级本条没有规定最低被引次数、期刊分区、影响因子或作者必须属于受评单位，系统不得自行添加这些门槛。

| 事实编号 | 要核验的问题 | 自动输出 | 遇到什么情况交人工 |
|---|---|---|---|
| C1-F1 论文身份 | PDF 的题名、作者、DOI 对应同一外部文献吗？ | 字段逐项对照、候选文献与原始记录链接；标识符冲突单列 | 同名论文、作者缺失、多个候选、扫描识别不清、DOI 与题名冲突 |
| C1-F2 发表载体 | 记录是期刊论文、会议全文、会议摘要、预印本、学位论文，还是其他类型？ | 原始类型与标准化类型；期刊/会议、卷期页码或文章号 | 预印本或会议摘要是否可采纳尚无评价口径；类型冲突或缺失 |
| C1-F3 时间 | 在约定的评价基准日之前是否已经按规定方式公布？ | 网络发表、纸本发表、预印本发布等日期及其精度，分别与基准日比较 | 只给年份且与基准日交叉、在线/纸本日期冲突、尚未设基准日 |
| C1-F4 版本与状态 | 所交版本是否与外部记录相符，有无已报告的撤稿、更正等情况？ | 版本、更新记录、检索来源与时间；明确“未发现记录”的覆盖范围 | 已发现撤稿、更正涉及关键结论；只有预印本而声称正式出版；状态无法核实 |
| C1-F5 文件一致性 | 上传正文是否与可获得的权威版本一致？ | 如能取得合法可用的官方全文，展示段落/表格差异；否则标“全文未核对” | 只有元数据、官方全文不可获取、文本存在实质差异、OCR 无法确认 |

以上是 C1 的事实输出字段，共用下面的五条实现路线，并非本轮额外开启五个讨论议题。日期口径和可接受文献类型是拟新增的项目评价配置，尚不是 Excel 已规定的条件。仅有元数据匹配时，只能确认书目信息匹配，不能宣称上传的全部正文真实、完整、未被改动。不同数据库可能使用同一上游元数据，多源一致不能简单计为多份独立证据。

#### C1.2 五个候选方案

##### P1 DOI 精确查询：Crossref + OpenAlex

- **适用材料**：有 DOI 的期刊论文或会议论文。自动化级别 A/B，文档抽取可使用 C 级辅助。
- **步骤**：从论文首页、题名区、页脚及 PDF 元数据抽取候选 DOI，并保存位置；排除参考文献中的 DOI。规范化后查询 Crossref `/works/{doi}`，必要时查询 `/works/{doi}/agency`，识别注册机构；Crossref 未收录不代表 DOI 或论文不存在。按 DOI 查询 OpenAlex，补充检索记录和可用的被引数据。
- **比对**：题名、作者、载体、年份、卷期页码/文章号、文献类型逐字段比对；记录缺失字段。遇到有效 DOI 指向另一篇文章，输出“标识符与材料冲突”，不根据 DOI 可解析就通过。
- **自动完成**：候选 DOI 提取、外部记录回查、书目字段一致性检查、已确定口径下的日期比较、证据卡片生成。发表状态与全文是否核对分别展示。
- **外部依赖与成本**：Crossref 公共 REST API 无需注册；OpenAlex 有基础免费使用，生产环境应配置 API key、请求预算、缓存及限流。不能把“有免费额度”写成“长期无限免费”。当前只核实官方文档，尚未用本项目材料实测。[S1][S2]
- **局限与人工兜底**：无 DOI、非 Crossref 登记、作者/单位元数据缺失、出版类型或日期冲突时转其他路线或 P5；全文被替换但书目信息相同，单靠本方案不能发现。
- **建议**：作为有 DOI 材料的默认入口。被引次数仅作带来源和检索时间的附加信息，第1级不据此设门槛。

##### P2 中文文献授权接口：万方优先，机构文献服务补充

- **适用材料**：中文期刊、中文会议材料、无 DOI 文献。自动化级别 A/B。
- **步骤**：从材料抽取中文题名、作者、刊名、年份、卷期页码；调用获得授权的文献查询接口召回候选，再按详情记录逐字段比对。题名相似度只作排序，不能用单一的“≥0.9”阈值代替核验。
- **已查证的接口事实**：万方官网公布了文献查询接口 `POST https://api.wanfangdata.com.cn/topic_read/paper`，要求应用 key 和签名，列出题名、作者、机构、发表年、刊名、DOI、卷期页码及被引量等返回字段。该接口有 HIGH/NEW/DEGREE/REVIEW 类型参数，不能据此承诺覆盖任意论文。[S3]
- **更适合核验的候选入口**：万方发布的开放检索接口目录还列出 `/openwanfang/getQuery` 和按文献 ID 取详情的能力，可围绕题名与作者检索。是否向本单位开放、鉴权方式、可用资源库、精确匹配效果、返回字段和留存权限，需要获得接口账号后逐项验收。[S4]
- **备选来源**：NSTL 官方服务申请页提供机构接口合作入口。CNKI、维普只列作后续商务/接口核实对象，当前没有本项目可调用接口的证据，不假定已有普通订阅就具备 API 权限。[S5]
- **自动完成**：中文文献定位、书目一致性与日期检查、返回记录留存；仅给发表年的记录保留年精度。
- **外部依赖与成本**：机构授权或采购；费用、配额、覆盖范围未取得报价，当前不填写金额。没有 API 权限时直接提供 P5 人工检索入口。
- **局限与人工兜底**：新刊入库滞后、会议论文覆盖不足、同题同名或数据库字段缺失时人工核对期刊目录和正文。查重检测 API 与文献检索 API 是不同能力。
- **建议**：作为中文材料的主要候选路线，与 P1 并列保留；接入前置条件是取得合适的检索/详情授权。

##### P3 无标识符的题名检索：OpenAlex / Semantic Scholar

- **适用材料**：无 DOI、DOI 无法读取、会议或英文材料。自动化级别 B；完成严格匹配后可形成具体书目事实。
- **步骤**：提取题名、作者、发表年、载体；使用 OpenAlex 的 `search` 或 Semantic Scholar 的论文检索端点获取有限候选，按作者、年份、载体等再匹配，保留候选差异。命中 DOI 后回到 P1，存在出版方链接时可进入 P4。[S2][S6]
- **AI 的位置**：可帮助修复 OCR 分段、识别中英文题名变体并排序候选；每个抽取字段必须返回材料页码与原文。AI 不得编造 DOI、作者、刊名或把模型已有知识当作检索证据。
- **自动完成**：多字段召回、候选排序、跨源记录对照、识别缺项；精确门槛需要使用标注样本校准。
- **外部依赖与成本**：有基础 API 使用方式，但存在密钥、限流和使用条款要求；以当前官方接口条件配置，保留来源标注。[S2][S6]
- **局限与人工兜底**：检索命中预印本不能直接视为正式期刊发表；同题、译名及预印本/正式版合并可能误配。只有一个近似候选仍不等于确认，交 P5。
- **建议**：用来扩大查全率。对无法取得强标识符或出版方核实的候选，不自动做整项通过结论。

##### P4 出版方或会议官网直核，并按需比较官方全文

- **适用材料**：有正式文章链接、数据库尚未收录的新文章、元数据冲突，或需要核对上传正文。自动化级别 A/B。
- **步骤**：从 DOI 解析结果、已核实期刊/出版方域名或会议正式论文集进入文章页；读取页面可用的书目元数据、出版日期、卷期/文章号及更正撤稿链接；必要时核对当期目录。支持期刊实际提供的结构化字段，不假定各站格式一致。出版页常见 `citation_title`、`citation_author`、`citation_publication_date` 等元数据标签有公开说明。[S7]
- **全文比较**：若获得合法可用的出版方 PDF/XML/HTML 全文，则按段落和表格比对。字节哈希相同可说明两个文件完全相同；哈希不同只说明字节不同，水印、分页或版本差异仍需进一步对照。对核心结论或数据存在差异的情况标记具体位置。
- **自动完成**：已支持站点的字段提取、目录交叉检查、日期比较、网页留证与可用全文差异定位。截图仅是留证手段，结构化事实才用于核验。
- **外部依赖与成本**：公开元数据通常可直接读取；全文受访问权限与许可约束；每种出版平台有适配和维护成本。不得把任意用户输入 URL 当成已核实出版方。
- **局限与人工兜底**：遇到登录、验证码、拒绝自动访问、版式变化或无可用全文，交 P5；出版社域名与假冒期刊页存在歧义时人工确认。
- **建议**：先支持明确的出版平台和已核实链接，用于处理冲突与新文献；不要在 PRD 中承诺自动访问所有期刊网站。

##### P5 人工核验与补证：始终可用

- **适用材料**：上述路线未覆盖、未命中、互相矛盾或权限不足的所有情况。自动化级别 D，系统仍自动整理已有查询过程。
- **步骤**：评价员打开系统生成的检索入口，核对正式记录和论文原文，填写“确认/有冲突/证据不足”，保存记录链接、日期、必要截图/摘录、审核人、理由及所核对的事实项。必要时由评价员联系期刊、作者或资料提供方补证。
- **系统承担**：预填已抽取信息、展示冲突字段、保存审核记录、形成证据说明、提示补充材料；不让评价员从头再录入所有信息。
- **依赖与成本**：人工工时及数据库访问权限；资料不可获得时允许保持“未能确认”，不强迫二选一。
- **边界**：人工结论保留自动核验的原记录，并注明采纳或覆盖理由。本轮不会发送任何函询；将来的对外函询应由评价员明确发起。

#### C1.3 推荐组合与结果规则（待确认）

五种路线可组合，不要求五选一：有 DOI 先 P1；中文或无 DOI 材料按授权和语种进入 P2/P3；存在冲突、新发表或全文核对需求时使用 P4；无法得出足够证据的事实进入 P5。

| 核验结果 | 系统建议行为 |
|---|---|
| 外部记录与上传材料的身份字段唯一对应，且配置已确定 | 对身份等已核实事实自动标“已核验”，保存字段对照和来源 |
| 只找到外部元数据，未取得官方全文 | 身份可核验；全文状态保持“未核对”，不得宣称整份 PDF 无篡改 |
| DOI 对应另一题名，或作者、关键内容存在明确冲突 | 标记具体冲突并要求复核，不能让相似度平均分掩盖冲突 |
| 没有命中，或不在某数据库覆盖范围 | 标“未检索到”，继续替代路线/补证，不标“不存在” |
| 超时、401/403、限流、接口变更 | 标“查询未完成/接口不可用”，允许重试或人工，不作为负面证据 |
| 同一论文的多来源不同 | 并列呈现原始来源、版本与更新时间，交人工解决；不得简单多数投票 |
| 发现撤稿、更正、表达关注等更新 | 显示具体记录与日期；其对本条可采性的影响需人工判断，不自动推断研究基础全部无效 |

拟采用两层结论：事实检查点可以自动核实；整条 TRL“满足/不满足/不适用”在本阶段仍由评价员确认。人工主要处理冲突、缺项、规则解释和最终采纳，不重复抄录已核实书目。

**日期建议**：增加项目级 `evaluation_cutoff_date`，不能用上传时间或项目创建时间替代。网络/纸本/预印本日期分开记录。拟按不晚于基准日比较；只有年份时作为日期区间处理，跨基准日则待核实。Crossref 的 created/deposited/indexed 表示元数据处理时间，不能当作发表时间。[S8]

**引用数据建议**：保留 `source + count + retrieved_at + coverage_note`，不同库的被引数分别展示，不相加，不将缺失写成 0。TRL4-HW-1 的“被引用或采纳”在轮到该条时单独讨论，要核引用文章/采纳证明及其时间，当前累计被引数不能直接证明在历史基准日之前已被引用。

#### C1.4 在当前项目中的用户操作与记录

1. 评价员在 `TRL1-HW-1` 上传论文。系统解析 PDF，识别材料类型和候选 DOI/题名，展示所据页码；无法识别时允许评价员补填。
2. 后台执行已启用的核验路线。卡片分别显示身份、文献类型、日期、版本状态、全文核对情况，以及需要人工处理的具体原因。
3. 评价员可重试其他来源、修正抽取信息、补证或人工确认。修正不覆盖原始抽取结果；记录操作者与理由。
4. C1 完成后，仍需后续 C5 判断该文献对基本原理的支撑。仅在条目各必要事实处理完毕后，评价员在现有判定界面选择最终结果。

拟新增的核验记录至少包含：`check_item_id`、`checkpoint_code`、`evidence_file_id`、原文件 `sha256`、规则/检查点版本、解析版本、调用来源与接口版本、检索参数（去密钥）、检索时间、候选标识、返回记录或允许保存的摘要、字段级对照、页码/原文位置、事实结论、错误原因、人工决定与理由。模型调用另存模型/提示词版本，模型自报置信度不作为事实可信概率。

异步任务状态（排队、处理中、完成、失败）与事实结论分开。文件被替换/删除、基准日或规则发生变动，原记录仍留存但标记不再适用于当前判定；同一文件的解析可缓存，面向不同条目或基准日的结论须分别生成。已审核、锁定或出报告后的补查，不得悄悄覆盖已冻结结论。
